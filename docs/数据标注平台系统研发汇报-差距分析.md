## 1. 需求基准摘要（来自汇报文档）

- **基础支撑层**：用户与权限分级留痕；项目与任务（标注类型/规范/验收标准、按工作量分配、进度与效率统计）；数据管理（多格式上传、断点续传、全格式预览、JSON/XML/CSV 导出）；规范与预警（模板、示例截图、实时提示、违规预警）。
- **六模块**：图片（矩形/多边形/圆形/自由、语义/实例分割、关键点连线、分类场景属性）；视频（目标追踪、行为起止+主体、关键帧、分类）；3D点云（3D框、分割、关键点、分类、车道线）；4D（帧间追踪、动态框、车道线动态追踪、帧间复制）；文本（嵌套实体、情感、词性、分类、OCR校对、语义匹配）；语音（转写、情感、语种、分割、发音校对）。
- **效率扩展**：AI预标注、按项目定制、开放API、多语言。
- **审核运维安全**：批量+单条审核、错误类型统计；监控告警（邮件/短信）、备份回滚；加密/越权拦截/页面与导出水印/密码复杂度/短信验证/IP限制；三种部署、PC+平板、百万级批量。

## 2.5 竞品对照：钉钉数据标注平台（2026-11-24 TRAE/REA 静态分析）

> 来源：`reports/dingtag-platform-analysis/dingtag-platform-analysis.html`（对 ding-tag.dingtalk.com 前端 bundle 的只读逆向：276 路由/318 懒加载组件/59 API 字符串，未登录、运行时行为未验证）。其"对春科平台的 10 条建议"中，P0 质检闭环、P0 角色权限、P2 多租户、P2 统计分层、P3 开放平台/SSO **我们已全部具备**（见 §2）；真正的新增量是下表：

| 竞品能力 | 我们现状 | 差距性质 |
|---|---|---|
| **错题体系**（错题本+错误广场，把质检驳回变成可学习资产） | 无（仅驳回错误类型统计） | ❌ 新缺口，运营向 |
| **验收申诉仲裁**（供应商对驳回可申诉，平台裁判留痕） | 无申诉流，验收驳回即终局退回 | ❌ 新缺口，流程向 |
| **考试准入门禁**（ExamGate：考试通过才能接单，题库/试卷/组织级考试） | 仅培训课程+培训记录（`serviceops.py:485`），未与接单联动 | 🔶 半缺，需加考试会话与任务领取联动 |
| **数据资产沉淀**（方言词典×14、热词文档、规则文档跨项目复用） | 仅规范模板（spec_templates） | 🔶 半缺，可扩展模板体系为术语/热词库 |
| **CER 看板/标注员周期看板**（能力分层与稳定性度量） | 有通过率/错误分布，无周期稳定性视图 | 🔶 增强 |
| **AI 助手贴业务形态**（悬浮气泡读取当前任务规则做问答） | 有算子/问答能力但无"上下文内助手"形态 | 🔶 形态差异 |
| 语音/文本专精定位（朗读/剧本/长音频/方言生产线） | 我们走六模块全品类（按汇报文档战略） | 战略选择不同，非能力差距 |

**定位启示**：钉钉平台验证了"语音+文本深做 + 生产线管理"赛道的可行性，与汇报文档"全品类投标资格"路线不冲突——我们补运营层（错题/申诉/准入）时，可直接参考其"事前考试→事中规范→事后质检→长期错题"四层质量模型表述。

## 5. 实现注意事项（沿用）

- **保持 payload 兼容**：图片 `boxes/polygons/masks/keypoints/category/attrs`、点云 `boxes/keypoints/lanes/frames/seg/intensity` 已被 `scripts/import_datasets.py`（KITTI/nuScenes/DAIR）与导出（COCO/VOC/LabelMe）依赖；本轮新增字段均为增量扩展，继续遵守。
- **外部算法走算子框架**：新 AI 能力接 `operator.<name>.url` + 内置降级。
- **验收口径**：文档是立项汇报非招标条款；核心工具必须画布可交互、保存后可回显（现有 `payloadOf`/customPayload 模式照抄）。
- 改完跑：`python3 -m py_compile app/*.py && node --check app/static/*.js`，再按 README §6 演示路径冒烟。
