# 春科 vs 钉钉标注平台 · 深入对比分析

> 补充分析，配合 `dingtag-platform-analysis.html`（TRAE/REA 静态报告）阅读。
> 本分析基于：① 钉钉平台登录态供应商工作台实拍截图（杭州春客账号，2026-11-24）；② 公开登录页实测；③ 春科平台代码级核对。
> 分析重点：UI 与左侧导航、语音标注模块逻辑与产品设计。

## 1. 左侧导航：两种信息架构哲学

```
┌─────────────────────┐
│ [项目卡片]【集团会议…】 │  ← 当前项目上下文 + 返回首页
│ 【长音频短框】        │
├─────────────────────┤
│ ▾ 任务与数据          │
│   标注数据管理        │

│ ▾ 生产工作台  ← C位   │
│   长音频工作台        │  ← 按"生产流程"排序
│   长音频质检工作台     │
│   返修工作台          │
│   返修管理           │
│   交付工作台          │
│ ▾ 项目与团队          │
```

### 春科（项目平台，代码现状）

```
工作台 / 我的任务 / 任务大厅 / 问题清单 / 帮助中心 / 个人偏好（标注员）
工作台 / 质检中心 / 规则质检 / …（质检员）
+ 管理角色：验收中心 / 项目空间 / 数据集 / 模板中心 / 工作流 / 数据统计
底部：姓名 · 角色 · 租户/组织/团队
```

### 本质差异

| 维度 | 钉钉 | 春科 | 根源 |
|---|---|---|---|
| 导航一等公民 | **工作台**（长音频工作台/质检工作台/返修/交付） | **队列**（我的任务/任务大厅/质检中心） | 生产模式不同（见 §2） |
| 进入标注的路径 | 导航→工作台→在工作台内领/做任务 | 队列→任务行"标注"→标注页 | 同上 |
| 导航分组 | 按**业务职能**分组（任务与数据/生产/团队/统计），可折叠 | 扁平列表（角色过滤） | IA 设计取舍 |
| 项目上下文 | 顶部**项目卡片**常驻，随时返回项目 | 顶部租户切换器+面包屑，项目上下文在 `#/project/:pid` 路由前缀里 | 都有，表达方式不同 |
| 角色空间 | `/vendor` 一个空间内再"切换工作台" | 三入口（管理平台/租户平台/项目平台）按角色分流 | 钉钉是单一组织内多角色，我们是多租户平台 |

**判断**：钉钉的导航对**非技术标注员更友好**（"我今天去长音频工作台干活" vs "我在任务列表里找任务"）；春科的导航对**多项目多角色的管理场景更严谨**。我们的扁平队列式导航对图像/文本等件数制品类是合理的，但对语音长音频品类，"工作台先行"的模式更贴合生产习惯。

## 2. 生产模式：件数制队列 vs 时长制工作台

实拍截图的关键信息：项目【集团会议试标】10-15分钟/区分说话人，**目标时长 2h / 已分配 0h / 剩余可分配 2h**，按"小时"向下属子组织转分配，子项目名以下划线拼接后缀。

- **钉钉是时长制**：分配和结算的单位是小时（适合录音、长音频转写——产出时长可预估、条数不可预估）；供应商可以建子组织再二次分配（产能层级）。
- **春科是件数制**：任务包按条领取，`billing.price_per_k` 按千条计价（适合图像/文本——条数确定、单价透明）。

**对我们的启示**：语音客服类项目（如我们的"语音-客服话术质检"）按件数计价其实在商务上吃亏——音频时长差异大，同样一条通话标注，30秒和10分钟成本差 20 倍。钉钉按小时分配的模型在语音品类更合理。我们的任务模型（tasks 表）目前只有条数维度，**没有"时长配额"维度**；若要拿下语音大单，任务包需要支持按时长分配与结算。

## 3. 语音标注模块：逻辑与产品设计对比

### 3.1 任务模型

| | 钉钉 | 春科 |
|---|---|---|
| 生产结构 | 长音频**切分→轮次标注→评审**（LongAudioWorkbench 多轮次） | 单音频 ASR 一键分段→逐段修→提交 |
| 切分 | 专门切分工序（切分也是一道生产工序，可专人做） | ASR 自动分段 + 手动微调起止 |
| 轮次 | 多轮次结构（round），每轮可质检、返修 | 无轮次，一次提交进质检 |
| 明细 | "长音频标注和质检明细"独立导航项，工作量可追溯到段/轮次 | 返工历史有（task 级），段级工作明细无 |

### 3.2 波形与标注器交互

- **钉钉用 WaveSurfer.js**：波形可缩放、可滚动、region 拖拽精准，10-15 分钟会议音频能 zoom 到句子级操作；配合 MediaRecorder 录音、SSE 实时通知。
- **春科用自绘 canvas 波形**（`drawWave`：1400 块峰值降采样 + 分段泳道）：整文件一屏显示，**不可缩放**。对 30 秒-2 分钟的客服通话够用；对 10-15 分钟会议长音频，分段精度受限于整屏像素密度，长音频场景是硬伤。
- 转写联动双方都有（点文本跳音频位置）。快捷键、倍速、说话人/情绪/事件字段双方基本对等。

### 3.3 规范与规则的呈现

- 钉钉：标注页内**规则面板** + AI 助手**读取当前页面临时规则**做问答（`/api/ai-chat/temporary-rules`）——规则是"问得到"的。
- 春科：本轮刚上的**规范面板**（spec 条文+示例截图）+ 违规实时预警 + 质检算子字符级高亮——规则是"看得见、被检查"的。
- 评价：我们"强制校验"强于钉钉；钉钉"随时可问"的形态补了我们 AI 助手缺失的一环。两者合体是最优解。

### 3.4 质量四层模型（差距最大处）

```
钉钉：  考试准入(事前) → 规则面板(事中) → 质检抽检(事后) → 错题本/错误广场(长期)
春科：  培训记录(弱)  → 规范面板(已有) → 质检+验收(强)  → 错误类型统计(弱)
```

- **考试门禁**（ExamGatePage：不通过考试进不了生产）我们没有，培训考核只有课程+记录（`serviceops.py:485`），未与接单联动；
- **错题本/错误广场**（把每次驳回变成标注员可复习、平台可统计的资产）我们没有；
- **申诉仲裁**（供应商对验收结果申诉，平台裁判）我们没有。
- 我们强于钉钉的：验收独立成第三级（他们验收后无申诉之外的复核层）、驳回错误类型结构化（漏标/框选偏差等）。

## 4. UI 视觉语言

- **钉钉**：浅色主题、Lucide 线性图标、大留白、卡片圆角，右侧 AI 气泡常驻——"生产线工具"质感，面向非技术一线人员；页面甚至内置 "Thinking..." AI 加载态，AI 存在感强。
- **春科**：深色主题、密集数据表格、信息密度高——"工程控制台"质感，面向项目经理与熟练标注员；AI 能力以"算子按钮"形式存在，无统一助手入口。
- 评价：投标演示时钉钉的浅色界面在"标注员易用性"叙事上加分；我们的深色控制台在"平台治理能力"叙事上加分。若补 AI 助手，悬浮气泡+读取当前任务规范是低成本高感知的切入点。

## 5. 可落地建议（按投入排序）

1. **波形可缩放**（P1，语音竞争力核心）：引入 WaveSurfer.js 或给现有 canvas 加 zoom/pan——长音频项目的前提。改动点：`app/static/app.js` `drawWave/loadAudio`。
2. **任务包支持时长维度**（P1，商务前提）：tasks/task_packages 加时长配额字段，领取与结算按小时；改动点：`db.py` tasks 表、`enterprise.py` 任务包、`main.py` 领取逻辑。
3. **错题本**（P1，运营向）：驳回时勾选的错误类型已结构化（qc_records.error_types），把它按标注员聚合成"我的错题"页即可，数据已经在那。改动点：复用 `/api/quality/error-types`，新增按人聚合查询+前端页。
4. **考试门禁**（P2）：题库+试卷+考试会话可复用模板编排的组件体系；关键是 ExamGate 接到任务大厅领取接口前。改动点：`serviceops.py` training 扩展 + `main.py` claim 前置校验。
5. **申诉流**（P2）：验收驳回增加"申请仲裁"分支，平台角色仲裁留痕。改动点：`main.py` acceptance 状态机扩展。
6. **导航加"生产工作台"分组**（P3，体验）：项目平台内按模态把"语音工作台/图像工作台"作为任务大厅的并列入口（不改底层路由，只是聚合视图）。
7. **AI 助手气泡**（P3，感知）：读取当前任务 instruction/spec 做规则问答，接现有 `llm` 算子。

## 6. 运行态实拍（二）：长音频任务池页与拉框标注工作台

> 证据：登录态实拍两页（供应商工作台 `/vendor/project/:id/long-audio` 及其任务详情），URL、按钮、字段均来自截图。结合 §5 已确认的我们侧实现状态对比。

### 6.1 任务池页（长音频拉框标注）

**钉钉**：
- 顶栏「刷新 + 领取任务」；明示语"任务领取后归属于你，**关闭页面不会释放**；草稿实时保存，下次进入可继续"
- **我标注中的任务**（置顶区）：任务 #11074112 · 2:04 · 共 30 框 · 已标注 0 · 待标注 30 →「继续标注」
- **待领取任务池 7**（卡片墙）：每张卡 = 任务号 + 时长（0:21）+ 共 N 框 + 已标注/待标注 +「开始标注」

**春科（任务大厅 `pageHall` + 我的任务）**：
- 任务包卡片已有**时长配额**（目标/已分配/剩余 h，来自 task_packages.quota_minutes），比他们多一层商务维度
- 「长音频切分工序」已上线（`/api/jobs/audio-split`）：按分钟切分→每段生成携带 est_minutes 的待领取任务，支持专人切分、多人分轮（批次名=轮次）
- **差异**：① 我们的大厅是表格行，卡片上**没有"已标注 X · 待标注 Y"的段级进度**，只有领取后才知道剩多少；② 没有"我标注中"置顶区+「继续标注」快捷入口（需到我的任务里找）；③ 领取语义对等（我们领取锁 vs 他们声明不释放）

### 6.2 拉框标注工作台（核心页）

| 能力 | 钉钉（实拍） | 春科（代码核对） | 差距 |
|---|---|---|---|
| 波形视图 | **双视图**：顶部整段 minimap + 下部缩放详情，时间标尺 | 单视图 1400 块降采样 | ❌ 长音频精度受限 |
| 波形缩放 | 滑块 + 百分比 +「全长」适配 | 无 | ❌ |
| 建段方式 | **波形上拖拽拉框**直接建段 | ASR 自动分段 /「新增段」按当前播放时刻+3s 默认 / 起止手输 | ❌ 无拖拽建段 |
| **段级状态机** | 待标注→草稿→已完成；统计 chips；过滤（全部/待标注/草稿/已完成）；「下一个待标注/下一个草稿」快速跳转 | 段无状态（仅任务级 draft） | ❌ 生产力核心差距 |
| 说话人 | **说话人样本**：S0/S1 各带试听按钮与段数，+新建说话人 | 段内下拉选择说话人 | ❌ 无样本音参照 |
| 全文转写 | 「全部转写框」折叠区连续全文 | 仅分段 textarea | ❌ 无聚合阅读视图 |
| 难度标签 | 每段 easy 标记 +「仅看 easy」过滤 | 无 | ❌ 可按难度分派 |
| 规则入口 | 「作业规则」「标注规则」页签 + **方言辞典** | 规范面板（本轮新增）≈作业规则；无辞典 | 🔶 词典类资产缺失 |
| 转写来源 | 上游预置转写框（项目带文本） | ASR 一键预识别（自服务）+ 区间转写 | ✅ 我们更强 |
| 段字段 | 说话人+文本（该项目维度） | 说话人/情绪+强度/语种/事件/发音校对 | ✅ 我们更强 |
| 质检辅助 | 未见 | 字符级规则质检算子、重叠发言检测 | ✅ 我们更强 |
| 保存 | 显式「保存草稿」 | 自动保存（实测 10:28/10:34 连续落库） | ✅ 我们更好 |

**段级状态机是这页最值得抄的设计**：它的生产力闭环是"领取任务（30 框）→ 逐段过状态（待标注→草稿→已完成）→ 列表过滤+下一个待标注驱动节奏 → 卡片进度（已标注 X/待标注 Y）反馈成就感"。我们段数据已经在 payload.segments 里，加 `status` 字段 + 过滤导航 + 卡片进度聚合即可，改动集中在 `app.js` 音频工作台与任务大厅查询。

**采纳优先级修订**（并入 §5）：P1 增加「段级状态机+波形拖拽建段+说话人样本」（三件套一起做才形成体验闭环）；P2 增加「任务卡片段级进度+我继续标注置顶区」；难度标签可作为任务包字段顺带。
